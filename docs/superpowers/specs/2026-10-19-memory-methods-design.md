# Wanki как приложение для запоминания чего угодно — дизайн

**Дата:** 19.10.2026
**Статус:** согласовано в разговоре, ждёт утверждения документа
**Основа:** Wanki (этот репозиторий). Memoryzer (`~/Documents/Projects/Memoryzer`) — источник идей, не кода и не данных.

Пометки: **(польз.)** — решил пользователь; **(моё)** — моё решение, пользователь его не утверждал, список таких
решений — в конце; без пометки — следствие из уже решённого или из кода.

## 1. Зачем

Пользователь хочет одно приложение, в котором есть все работающие способы запоминать и заучивать: не только
языковые карточки и письмо от руки, как сейчас в Wanki, а и формулы по физике и математике, исторические даты,
стихи, небольшие тексты и т. д. **(польз.)**. Коран — один из многих вариантов того, что человек может захотеть
выучить, а не обязательная часть приложения; всё, что нужно только для него, — на втором плане **(польз.)**.
Memoryzer задумывался как такое приложение, но Wanki ушёл дальше (этапы 1–3 готовы, стоит у пользователя на
телефоне с настоящими данными), поэтому идеи Memoryzer переносятся в Wanki, а не наоборот.

Главное, что должно появиться в первую очередь **(польз.)**:
1. **Проверка голосом** («Mistake Detection», как в Tarteel): человек рассказывает вслух, приложение сразу сверяет с
   заучиваемым текстом. Два уровня: простой — правильность и порядок слов; продвинутый — произношение.
2. **Исчезающие подсказки** (vanishing cues): текст скрывается постепенно, пока не расскажешь его целиком.
3. **Шесть приёмов с доказанной пользой**: интервальное повторение, перемешивание, вспоминание вместо
   перечитывания, объяснение «почему», конкретные примеры, слово + картинка.
4. **Сабак / сабки / манзиль** — схема заучивания длинных текстов из практики хифза: новое, недавнее, давнее.

Остальные найденные методы тоже нужны — «как можно больше функций» **(польз.)**: первые буквы, цепочка строк,
запись своего голоса, мнемотехника для дат, лента времени, маски на картинках, ИИ-подсказки, формулы с пропусками.

## 2. Что решено с пользователем

- Основа — Wanki. Данные Memoryzer не переносятся (там ничего нет) **(польз.)**.
- Захвата слов из других приложений (выделение текста, «Поделиться») **нет**: слова добавляются в самом Wanki **(польз.)**.
- **Графа понятий из Memoryzer нет.** Вместо него — многоязычные заметки: одна заметка `word / слово / 言葉`,
  на повторении показывается одна сторона, остальные надо вспомнить **(польз.)**. У каждой стороны своё расписание,
  сначала включено только узнавание, остальные стороны открываются по мере усвоения **(польз.)**.
- По возможности всё работает **без интернета**; продвинутым функциям сеть разрешена **(польз.)**.
- Проверка голосом — два варианта: простой (последовательность и правильность текста по распознанной речи) и
  продвинутый (произношение) **(польз.)**.
- **Тексты повторяются по FSRS по умолчанию; для любого текста можно выбрать план сабак/сабки/манзиль** **(польз.)**.
- Коран — на втором плане: встроенный текст, чтецы, особая модель распознавания и таджвид — потом **(польз.)**.
- Порядок этапов — раздел 5; пользователь согласился и разрешил решать остальное самому **(польз.)**.

## 3. Цели, не-цели, анти-цели

**Цели**
- Выучить стих, отрывок или любой другой текст по кускам с исчезающими подсказками и повторять его по FSRS или по
  плану сабак/сабки/манзиль.
- Рассказать вслух без интернета и сразу увидеть пропущенные, лишние, неверные слова и сбитый порядок.
- Учить два-три языка одной колодой.
- Учить формулы, даты, факты теми приёмами, которые им подходят.

**Не-цели**
- Граф понятий, кандидаты на слияние, экран «здоровье графа» из Memoryzer.
- Захват из других приложений, «Входящие» как отдельный этап разбора.
- Перенос данных или кода Memoryzer как обязательное требование (код можно подсматривать).
- В этапах A и B — ничего, что нужно только для Корана (раздел 10, «Пакет для Корана»).
- Синхронизация (этап 7 Wanki по-прежнему отложен).
- Публикация в магазине.

**Анти-цели** (если так получится — это провал, даже если «работает»)
- **Проверка голосом, которая часто считает правильное неправильным.** Ложные «ошибка» убивают доверие быстрее,
  чем пропущенные ошибки. Сомнительное слово показывается как «не расслышал», а не как ошибка, и пользователь
  может поправить вердикт.
- **Завал после пропущенных дней.** Пропуск не должен складывать двойную норму или сотни повторений.
- **Потеря данных на телефоне пользователя** (миграции, переустановка).
- **Искажение текста, который человек заучивает.** Текст хранится и показывается ровно таким, каким его сохранили;
  любая нормализация (регистр, огласовки, варианты букв) — только внутри сравнения.
- **Базовые функции, которым нужен интернет.**

## 6. Этап A — Тексты

### 6.1 Что это
Новый вид материала рядом с колодами: **текст** — стих, отрывок прозы, речь, молитва, сура — что угодно, что надо
помнить дословно и по порядку. Текст делится на **куски** (строка стиха, предложение, аят). Учится режимами для
текстов (6.3), повторяется по одному из двух расписаний (6.5).

### 6.2 Добавление
- Вставить или набрать текст, выбрать язык (по умолчанию — определить через уже подключённый ML Kit Language ID)
  и вид: стих / проза.
- Деление на куски: стих — по строкам; проза — по предложениям (`android.icu.text.BreakIterator`). Деление можно
  поправить вручную (склеить/разрезать).
- У куска — необязательное поле «Перевод/пояснение».
- Направление письма по языку: арабский (и любой RTL) — справа налево, строки и куски в правильном порядке.
  Встроенных текстов (в том числе Корана) нет — это «Пакет для Корана».

### 6.3 Режимы заучивания (для куска, порции или всего текста)
1. **Чтение и слушание.** Полный текст; озвучка через существующий `Speaker` (TTS), если для языка есть голос.
2. **Исчезающие подсказки.** Уровни: весь текст → скрыто ~25% слов → ~50% → ~75% → только первые буквы → ничего.
   Скрытые на уровне k слова остаются скрытыми на уровне k+1 (вложенный детерминированный порядок, зерно — ид
   куска) **(моё)**, чтобы от повтора к повтору прятались одни и те же слова. Скрытое слово — пропуск по длине
   слова; тап открывает слово и считается подсказкой. Переход на следующий уровень — кнопкой или автоматически,
   когда уровень пройден без подсказок.
3. **Первые буквы.** Видна только первая буква каждого слова. Дополнительно — ввод первой буквы с клавиатуры с
   проверкой (как в The Bible Memory App); сравнение без регистра и без огласовок.
4. **Цепочка.** Виден предыдущий кусок, текущий скрыт; вспомнил → открыл → отметил. Наращивание: 1, 1–2, 1–3…
5. **Рассказ целиком.** Всё скрыто; рассказываешь (вслух или про себя), потом открываешь и **тапаешь куски, где
   ошибся**. В этапе B сюда подключается проверка голосом, и отметка ставится сама.

Слова для японского и китайского (без пробелов) — через `BreakIterator.getWordInstance` с нужной локалью;
для арабского — по пробелам, первая буква — изолированная форма.

### 6.4 Свой голос
Запись себя на кусок или порцию, проигрывание по кругу. Файлы — в `files/media/`.

### 6.5 Повторение: FSRS (по умолчанию) или сабак/сабки/манзиль
Общее для обоих расписаний:
- **Новые куски** вводятся порциями: размер порции — настройка текста (например, 4 строки или 3 предложения в
  день). Новая порция проходит режимами из 6.3 и считается выученной, когда рассказана целиком без подсказок и
  ошибок. Не выучена сегодня — завтра та же порция, следующая не наступает (пропуски не копятся).
- **Активных текстов может быть несколько**, у каждого своя порция; текст можно поставить на паузу **(моё)**.
  На экране «Сегодня» для текстов видна суммарная нагрузка, а при включении нового текста — сколько он прибавит
  в день.
- **Уже знакомый текст** (или его часть) можно отметить выученным, минуя новые порции **(моё)**.
- Свободный «рассказать весь текст» в любой момент — это практика: пишется в журнал, отмечает слабые куски, но
  расписание не двигает **(моё, как тренировка почерка в Wanki не трогает FSRS)**.
- Ежедневное напоминание (`reminders`) учитывает и тексты.
- По каждому тексту видно: сколько выучено (кусков, %), где чаще ошибки (слабые куски подсвечены).

**FSRS (по умолчанию) (польз.)** — у каждого выученного куска своё состояние FSRS **(моё: единица — кусок)**.
- Повторение куска — режим «Цепочка»: виден предыдущий кусок как подсказка, текущий надо рассказать. Куски одного
  текста на сегодня идут в порядке текста.
- Оценка (самооценка, в этапе B — по голосу) **(моё)**: без ошибок и подсказок → Good (очень быстро → Easy);
  ошибки исправлены подсказками → Hard; не вспомнил или много ошибок → Again. Те же четыре оценки уходят в FSRS.

**Сабак / сабки / манзиль (по выбору для текста) (польз.)**
- **Сабак** — новая порция (см. выше).
- **Сабки** — всё выученное за последние 7 **учебных** дней (дней, когда сабки был сделан) **(моё)**,
  рассказывается каждый день подряд. Кусок с ошибкой остаётся в сабки ещё на полное окно.
- **Манзиль** — всё, что старше окна. Указатель идёт по выученному в порядке текстов и каждый день берёт следующую
  долю (≈ всё / 14, с округлением до целых кусков, лучше до границ текста). Пропущенный день — указатель стоит,
  круг удлиняется, двойной нормы нет. Кусок с ошибкой в манзиле возвращается в сабки.
- Окно сабки (7) и длина круга манзиля (14 дней) — общие настройки **(моё — значения из источников)**; манзиль идёт
  по всем текстам с этим планом сразу.
- Порядок частей на экране — сабак → сабки → манзиль **(моё)**; делать можно в любом порядке.

**Смена расписания у текста** — в любой момент, без потери истории **(моё)**:
- FSRS → хифз: куски, выученные за последние 7 учебных дней, — в сабки, остальные выученные — в манзиль.
- Хифз → FSRS: журнал рассказов каждого куска прогоняется через FSRS (как уже делает `anki/ScheduleReplay` для
  истории Anki) → состояние FSRS.

### 6.6 Данные
БД v6, миграция 5→6 с тестом **(моё — точные имена за исполнителем)**:
- `texts` — ид, название, язык, вид (POEM/PROSE), расписание (FSRS/HIFZ), размер порции, активен/на паузе,
  порядок, `updatedAt`, `deleted`.
- `text_pieces` — ид, текст, индекс, содержимое, перевод/пояснение, выучен (дата); поля FSRS (state, stability,
  difficulty, due, lastReview, reps, lapses); поля хифза (часть плана NEW/SABAQ/SABQI/MANZIL, начало окна сабки);
  `updatedAt`.
- `recitations` — журнал (только дописывается): кусок или диапазон, когда, режим, расписание и часть плана,
  оценка, ошибки (какие куски, с этапа B — какие слова), подсказки, длительность, практика или повторение.
- Указатель манзиля — отдельная строка или настройка.

Резервная копия и восстановление должны включать новые таблицы (БД копируется целиком — проверить тестом).
Сейчас `Backup.autoBackupIfDue` пропускает автокопию, если нет колод, — условие расширить на тексты. Записи своего
голоса лежат в `files/media/`: они входят в ручную копию и, как остальное медиа, не входят в ежедневные
автокопии **(моё)**.

Логика обоих расписаний (выбор кусков на сегодня, сабки/манзиль, переход между расписаниями) — чистый JVM-код
без Android, с тестами.

### 6.7 Где это в интерфейсе
Без новой вкладки: на экране «Колоды» — раздел или переключатель «Тексты» со строкой «Сегодня» и списком текстов
**(моё — раскладку решает исполнитель, сверяясь со skill `android-ui-design`)**.

### 6.8 Готово, когда
- Добавлены стих (вставкой) и отрывок прозы, а также текст на арабском (RTL) и японском; деление правится.
- Все пять режимов работают для ru, ja и ar, включая исчезающие подсказки с вложенными уровнями.
- Текст по FSRS: новые порции, повторение кусков цепочкой, оценки уходят в FSRS.
- Текст по хифзу: «Сегодня» правильно раскладывает куски по сабак/сабки/манзиль, в том числе после пропущенных
  дней и ошибок.
- Смена расписания в обе стороны сохраняет историю (JVM-тесты на всё это).
- Миграция 5→6 проходит `MigrationTest`; смоук-тест открывает текст и проходит уровень подсказок.

## 7. Этап B — Простая проверка голосом (без интернета)

### 7.1 Сначала проба движков
Короткая выброшенная проба (spike), чтобы выбрать движок. Кандидаты:
- встроенный распознаватель Android на устройстве (`SpeechRecognizer.createOnDeviceSpeechRecognizer`, API 31+;
  языки зависят от телефона, проверяются через `RecognitionSupport`);
- **Vosk** (модели ~50 МБ, есть ru/en/ja/ar и др., потоковый, можно сузить словарь до заучиваемого текста);
- **Whisper** через whisper.cpp или sherpa-onnx (готовые официальные модели).
Критерии: точность по словам на заранее известном тексте, задержка, размер, полностью без сети, лицензия,
работа с minSdk 29 (на API 29–30 встроенного распознавателя на устройстве нет — нужен запасной движок или честное
«недоступно»). Языки: ru, en, ja, ar; zh и ko — по возможности. Для проверки — записанные аудиофайлы (Common Voice
и т. п.) и эмулятор; **не телефон пользователя**. Можно выбрать разные движки для разных языков. Итог пробы —
запись в PROGRESS и короткое решение в этом документе.

### 7.2 Сравнение с текстом
Мы заранее знаем, что должно прозвучать, поэтому задача — выравнивание, а не свободная диктовка:
- Нормализация обеих сторон: регистр, пунктуация, NFKC; для арабского — снять огласовки, унифицировать варианты
  алифа/хамзы/та-марбуты/алиф-максуры; для японского — катакана→хирагана (кандзи против каны — см. ниже).
- Выравнивание по словам (динамическое программирование, как расстояние Левенштейна по словам) с нечётким
  сравнением слова (порог по расстоянию правки).
- Итог по каждому ожидаемому слову: **верно / пропущено / неверно / не расслышал**; плюс **лишние** слова;
  пара «пропущено здесь + лишнее то же слово рядом» — **не на месте** (сбит порядок).
- «Не расслышал» — когда уверенность движка низкая или расхождение похоже на ошибку распознавания (для японского —
  в первую очередь расхождение кандзи/кана, которое не удалось свести). Это не ошибка.
- Пользователь может нажать на слово и сказать «я сказал правильно» — вердикт меняется, факт пишется в журнал
  (полезно для настройки порогов).

### 7.3 Как выглядит
- Если движок потоковый — слова подсвечиваются по ходу чтения, как в Tarteel; скрытый текст открывается по мере
  произнесения (вместе с исчезающими подсказками). Ошибка показывается сразу, чтение не прерывается
  (по желанию — «останавливать при ошибке»).
- Если не потоковый — разбор сразу после окончания.

### 7.4 Где используется
- Тексты: режимы «Рассказ целиком» и «Цепочка», повторение по FSRS (оценка по правилу из 6.5) и по хифзу —
  отметки ошибок ставятся сами; ошибки по словам пишутся в `recitations` → список «слабые места» по тексту.
- Карточки: третий режим ответа **«Голос»** рядом с CLASSIC и HANDWRITING. Оценка — по тому же правилу, что для
  письма **(моё)**: < 60% слов верно → Again; иначе Hard/Good/Easy по подсказкам и времени (`RatingSuggester`).
  Что говорить **(моё)**: ответ карточки на языке колоды. В режиме «Голос» строки-подсказки вопроса (чтения, пиньинь
  — всё после первой строки) скрыты, иначе ответ просто читается с экрана; они же служат допустимыми вариантами
  ответа (японское слово можно сказать и тем, что распознаватель запишет каной). Для колод отдельных кандзи (много
  чтений у знака) голос доступен, но по умолчанию не включается.

### 7.5 Готово, когда
- Выбранные движки работают без сети после разовой загрузки модели; без модели — понятное предложение скачать.
- JVM-тесты выравнивания и нормализации (включая арабский с огласовками и перестановку слов).
- Текст из этапа A рассказывается голосом, ошибки отмечаются сами; карточка отвечается голосом.
- Release с R8 запускает распознавание (keep-правила).

## 8. Этапы C–E

### Этап C — Шесть приёмов по всему приложению
1. **Вспоминание вместо перечитывания** — уже так в повторении; во всех новых режимах сначала вопрос/скрытый текст,
   потом ответ.
2. **Интервальное повторение** — FSRS для карточек и текстов (есть/этап A), хифз для текстов по выбору.
3. **Перемешивание** — сессия «Всё вперемешку» по выбранным колодам. Чтобы языки не путались, у каждого языка
   постоянный цвет и бейдж везде (идея Memoryzer); цвет никогда не единственный признак.
4. **Объяснение «почему»** — поле «Пояснение» у заметки, показывается после ответа; после второго провала карточки
   — мягкое предложение дописать пояснение или мнемонику.
5. **Конкретные примеры** — поле «Примеры»; для готовых японских колод — предложения Tatoeba (CC BY 2.0 FR) с
   переводом (русским, где есть), собираются в `tools/decks/build.py`.
6. **Слово + картинка** — в редакторе карточки: картинка из галереи/камеры или быстрый рисунок на имеющемся холсте.

### Этап D — Многоязычные заметки
- Встроенный тип заметки с полями-языками (2–5), у каждого поля свой язык (`ru`, `en`, `ja`…). Колода создаётся с
  выбором языков и **опорного** языка (по умолчанию `ru`).
- Карточка на каждое поле: лицо — это поле, оборот — **все остальные**; пользователь вспоминает те, что знает,
  и оценивает себя (у каждой карточки своё расписание FSRS) **(польз.)**.
- Постепенное открытие **(польз.)**: сначала активны карточки, где лицо — изучаемый язык (узнавание). Карточка с
  лицом на опорном языке (воспроизведение) открывается, когда у всех карточек узнавания этой заметки интервал
  ≥ 21 дня (настройка колоды) **(порог — моё, из Memoryzer)**. Закрытые карточки не показываются и не считаются
  в лимитах (новая колонка или состояние карточки + миграция).
- Письмо от руки — когда на обороте есть поле CJK; голос (этап B) — ответ на одном из языков.
- Готовые колоды: ja/ru/en из тех же 6000 слов JMdict (там есть и русские, и английские значения), ko/ru/en из
  한국어기초사전.

### Этап E — Остальные методы
- **Формулы и пропуски:** создание cloze-заметок в редакторе (тип CLOZE уже есть после импорта Anki) и LaTeX:
  KaTeX в одном скрытом WebView при сохранении → картинка в кэш; в повторении показывается картинка.
- **Маски на картинке:** закрыть области картинки (карта, схема), каждая маска — карточка.
- **Даты:** тип «Событие ↔ год» в обе стороны; помощник мнемотехники (русский цифро-буквенный код: год → слова-
  образы); «дворец памяти» — свой маршрут мест, к которым привязываются записи; лента времени всех дат.
- **Проблемные карточки:** после N провалов подряд (по умолчанию 6) карточка приостанавливается и попадает на
  экран «Проблемные» с предложениями: мнемоника, картинка, пример, архив.
- **Защита от перегрузки:** прогноз нагрузки при добавлении/установке колоды («+20 слов = +35 карточек в день через
  две недели»); после перерыва — сначала то, что вот-вот забудется, и кнопка «растянуть долг на 7 дней».
- **Статистика:** тепловая карта занятий, пирамида зрелости, прогноз на 30 дней, разрез по языкам и по текстам.
- **ИИ-подсказки (сеть, свой ключ):** мнемоника-созвучие или пояснение к карточке, кэш по содержимому; ключ
  хранится зашифрованным (Android Keystore). Провайдер — на выбор исполнителя, по умолчанию Claude.

## 9. Этап F — Продвинутая проверка произношения (сеть)

- Языки: ru/en/ja/zh (тоны)/ko/ar — оценка произношения по словам и звукам.
- Начинается с исследования: облачные сервисы оценки произношения (поддержка нужных языков, цена, условия).
- Свой ключ пользователя, как в этапе E. Без сети — функция недоступна, простая проверка (этап B) работает.

## 11. Мои решения (пользователь их не утверждал — проверить при чтении)

1. Новые этапы обозначены буквами A–F и идут перед этапами Wanki 4–6.
2. В FSRS-расписании текста единица — кусок, повторение — цепочкой (предыдущий кусок как подсказка); оценка:
   чисто → Good/Easy, с подсказками → Hard, не вспомнил → Again.
3. Свободный рассказ всего текста — практика: отмечает слабые куски, но расписание не двигает.
4. Смена расписания текста в любой момент: FSRS → хифз раскладывает по сабки/манзилю, хифз → FSRS прогоняет журнал
   через FSRS.
5. План хифза: окно сабки 7 учебных дней, круг манзиля 14 дней, общий для всех хифз-текстов; порядок сабак →
   сабки → манзиль; пропуски не копятся.
6. Несколько активных текстов, у каждого своя порция; пауза; знакомый текст можно сразу отметить выученным.
7. Исчезающие подсказки — вложенные уровни 25/50/75%/первые буквы/ничего, одни и те же слова от повтора к повтору.
8. Модели распознавания скачиваются по запросу из официальных источников, а не лежат в APK.
9. Голосовой ответ на карточку оценивается по правилу письма (< 60% → Again); строки-подсказки вопроса в этом
   режиме скрываются и считаются допустимыми ответами; для колод кандзи голос не включён по умолчанию.
10. Порог открытия обратной стороны многоязычной заметки — 21 день; проблемная карточка — 6 провалов подряд.
11. Тексты живут внутри экрана «Колоды», без новой вкладки.
12. Автокопии без колод, но с текстами — делаются; записи голоса — только в ручной копии.
