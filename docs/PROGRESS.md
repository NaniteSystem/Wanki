### Колоды (путь в дереве → содержимое)
- `Японский::Кана::Хирагана`, `…::Катакана` — 46 + 25 (дакутэн), вопрос — ромадзи (Хэпбёрн), ответ — кана; письмо.
- `Японский::Кандзи::1 класс` … `6 класс`, `…::Средняя школа` (KANJIDIC grade 1–6 и 8 = все 2136 дзёё).
  Вопрос: значение (русское — из JMdict-слова, состоящего из одного этого кандзи, предпочтительно частого;
  иначе английские из KANJIDIC, до 3) + вторая строка с чтениями «он: ニチ、ジツ · кун: ひ、か» (до 3 каждого,
  кун с окуриганой как «つ(ぐ)»). Ответ: кандзи. Порядок — по частоте KANJIDIC.
- `Японский::Слова::0001–1000` … `5001–6000` — 6000 самых частых слов JMdict (ранг = min nfXX по ke_pri/re_pri;
  при равенстве — наличие ichi1/news1, затем порядок в словаре). Ответ — запись кандзи с лучшим приоритетом, или
  кана, если у первого значения пометка `uk`. Вопрос — значения (рус. из первых 1–2 значений, иначе англ.) + вторая
  строка — чтение (не показывать, если ответ сам кана).
- `Китайский::HSK 3.0::Уровень 1` … `Уровень 6`, `…::Уровни 7–9` (n1 506, n2 750, n3 953, n4 972, n5 1059,
  n6 1123, n7 5606 слов; слово — в самом низком n-уровне). Порядок — по частоте `q`. Вопрос — англ. значения
  (первые 2) + строка пиньиня; ответ — упрощённые иероглифы.
- `Корейский::Начальный (초급)`, `…::Средний (중급)`, `…::Продвинутый (고급)` — слова (`lexicalUnit=단어`) с уровнем.
  Вопрос — русский эквивалент (러시아어 lemma) первых 1–2 значений, иначе англ. (영어); ответ — writtenForm.
  Порядок — детерминированное перемешивание (sha1 слова), чтобы не шли подряд слова на одну букву.
- Все колоды по умолчанию в режиме «Письмо». До этапа 4 китайский и корейский проверяются только распознаванием.

### Формат в приложении
- `app/src/main/assets/decks/catalog.json` — список колод: `id`, `path` (массив имён), `language`, `mode`,
  `count`, `file`, `description`, `source`, `license`, `version`.
- `app/src/main/assets/decks/<id>.tsv` — строки `key\tfront\tback\ttags` (в полях `\n` записан как `\\n`).
- БД v4: в `decks` колонка `catalogId` (миграция 3→4 + тест). Ид заметок/карточек детерминированные:
  `<catalogId>:<key>` и `<catalogId>:<key>:0`. Повторная установка = обновление: новые карточки добавляются,
  у существующих меняются только поля, расписание не трогается.
- Экран «Готовые колоды» (меню «⋮» на экране колод и кнопка в пустом списке): по языкам, «Добавить» /
  «Обновить», прогресс установки.
- Демо-колоды при первом запуске больше не создаются (пустой список → предложение готовых колод);
  смоук-тест ставит колоду из каталога и работает с ней.
- `ReferenceRepository.get(char, language)`: KanjiVG только для `ja`; для `zh`/`ko` эталонов пока нет
  (этап 4 — Make Me a Hanzi и чамо).
- В повторении вопрос: первая строка крупно, остальные (чтения, пиньинь) — мельче и серым.

## Этап 3: полный импорт Anki — решения
- **Типы заметок** — таблица `note_types` (БД v5): `id`, `name`, `fields` (JSON имён), `templates` (JSON
  `[{name, q, a}]`), `kind` (STANDARD/CLOZE), `css`, `updatedAt`, `deleted`. Встроенный `basic` — константа в коде
  (не строка в БД), старые заметки работают как раньше.
- **Ид**: заметка `anki-<guid>`, карточка `anki-<guid>:<ord>`, тип `anki-<mid>` — повторный импорт не дублирует:
  существующие карточки не трогаются (расписание и история не удваиваются), поля заметки обновляются, если в Anki
  она новее (`mod`), а у нас не правилась.
- **Отображение**: вопрос/ответ рендерятся из шаблона Anki (`anki/AnkiTemplate.kt`: {{Поле}}, {{FrontSide}},
  {{#Поле}}/{{^Поле}}, фильтры text:/kana:/kanji:/furigana:/hint:/type:/tts, cloze {{c1::…::…}}) в HTML, затем
  `anki/CardHtml.kt` → блоки (текст / картинка / звук). Для `basic` всё как раньше.
- **Что писать**: стандартный тип — первое поле, которое есть в шаблоне ответа и нет в шаблоне вопроса
  (`writeFieldOrd`); cloze — текст пропусков c(ord+1). Режим «письмо» — если ответ в клетках (CJK/кана/хангыль).
- **Расписание**: `revlog` каждой карточки (ease 1–4, типы 0–3) прогоняется через наш FSRS → состояние и
  `review_logs` (cardState по ходу, durationMs = time); ручной сброс (тип 4, ivl 0) → снова новая; без истории:
  review-карточка → состояние из ivl/factor, новая → позиция = due Anki. queue −1 → приостановлена, −2/−3 → отложена
  до завтра. Карточки в фильтрованных колодах — в исходной колоде (odid). Лимиты колод из `dconf` (старая схема).
- **Медиа**: старая схема — `media` JSON, файлы как есть; новая (`collection.anki21b`) — `media` = zstd + protobuf
  `MediaEntries{entries{name=1,size=2,sha1=3}}`, файлы `0,1,2…` сжаты zstd. Кладутся в `files/media/` (имя
  очищается от путей). Картинки показываются в карточках, `[sound:]` — кнопка проигрывания. Резервная копия
  включает `media/`.
- **Новая схема Anki**: `notetypes`(config protobuf: kind=1, css=3), `fields`(ntid, ord, name), `templates`(ntid,
  ord, name, config protobuf: q_format=1, a_format=2), `decks`(name через 0x1F). Старая: JSON в `col.models`,
  `col.decks`, `col.dconf`.
- Редактор карточки показывает все поля типа заметки; браузер — первое поле и поле для письма.
